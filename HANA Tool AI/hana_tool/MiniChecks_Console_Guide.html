📋 Overview

What the app does and who it is for.

The SAP HANA Mini Checks Console is a lightweight, browser-based SQL execution environment specifically designed for SAP HANA DBA tasks. It runs as a local Python web server on your Windows workstation and opens automatically in your default browser.


The app combines an ad-hoc SQL editor with a curated library of SAP HANA mini-check scripts and a one-click "Basic Bundle" that runs 35 standard diagnostic queries in sequence and produces a single consolidated output file — ready to attach to a service ticket or review in Excel.


⚡

Zero Dependencies on the HANA Host

Connects over the standard hdbcli TCP port (default 30241). No SAP GUI, no HANA Studio, no VPN tunnel beyond network access to the DB port.

🔌

Offline-Ready

The hdbcli driver and Chart.js library are bundled locally. No internet connection is needed after installation.

📦

Basic Bundle

Runs 35 standard HANA diagnostic mini-check scripts in one click with a live progress bar, skipping any that fail, and downloads a single consolidated .txt output.

📊

Integrated Charting

Any query result can be visualised as Bar, Line, Pie, Doughnut, Polar Area, or Radar chart — with a Save PNG button.

📁

Mini Checks Library

A filterable sidebar lists all .sql/.txt files in the mini_checks\ folder. Click a script to load its SQL directly into the editor.

🗂️

Consolidate

After individual runs, select any combination of saved output files and merge them into a single timestamped review document.

🏗️ Architecture

How the app is structured internally.

The app is a single Python file that does two things simultaneously:


LayerTechnologyRole
Web serverhttp.server.ThreadingHTTPServer (stdlib)Serves the HTML UI and handles all API requests on 127.0.0.1:5000
UIVanilla HTML / CSS / JavaScript (embedded in the .py file)All UI is rendered in your default browser; no framework needed
HANA driverhdbcli.dbapi (bundled in lib\)Opens and manages the TCP connection to SAP HANA
Chart libraryChart.js UMD (optional, served from lib\)Powers the Chart tab — bar, line, pie, doughnut, polar, radar
REST APIJSON over HTTP (POST / GET)Browser calls local endpoints: /api/connect, /api/execute, /api/basic_bundle, etc.

ℹ️
The server binds exclusively to 127.0.0.1 (loopback). It is not reachable from the network — only from the local machine. Your HANA credentials are kept in memory only for the duration of the session and are never written to disk.

📥 Installation

How to install using the provided installer batch file.

Option A — Automated installer (recommended)

  1. Verify Python is installed Open a command prompt and run python --version. You need 64-bit Python 3.10+. If not installed, run python-3.14.6-amd64.exe from the hana_tool\ folder and check "Add Python to PATH".
  2. Run the installer Double-click install_minichecks_console.bat in the hana_tool\ folder. If you see a UAC prompt, click Yes.
  3. Choose an installation directory The installer asks for a target path. Press Enter to accept the default (C:\HANA_Tools\minichecks_console), or type a custom path (e.g. D:\Tools\minichecks).
  4. Wait for the copy and verification steps The installer copies all files, verifies the hdbcli import, checks port 5000 availability, creates run_minichecks.bat, and adds a desktop shortcut.
  5. Launch the app Double-click the "HANA Mini Checks v2" shortcut on the Desktop, or navigate to the install folder and run run_minichecks.bat.

Option B — Manual run (no install)

If you just want to run the app from the source folder without copying anything:

cd "C:\...\hana_tool"
python minichecks_console_V2.0.py

The browser opens automatically at http://127.0.0.1:5000.

⚠️
Keep the console window open. The Python process is the web server. Closing it stops the app. Press Ctrl+C in the console window to stop it cleanly.

🔌 Connecting to SAP HANA

The login modal that appears when the app loads.

When the browser opens, a Connect to SAP HANA modal appears. Fill in the fields:


FieldDefaultDescription
HostemptyHostname or IP of the HANA system (e.g. hana-host.example.com)
Port30241HANA SQL port. Formula: 3<instance>15 for SystemDB or 3<instance>41 for tenant. Adjust for your SID.
DatabaseemptyTenant database name (e.g. HP4). Not used for the connection itself but shown in the status bar.
UseremptyHANA database user (e.g. SYSTEM or a monitoring user)
PasswordemptyPassword — never stored on disk; lives in Python process memory only for this session

Press Enter in the Password field or click Connect. On success:

  • The modal closes.
  • The green dot (●) in the top-right corner lights up.
  • The status bar at the bottom shows host:port, database, and user.
  • The Run button, Mini Checks toggle, Basic Bundle, Consolidate, and Clear Outputs buttons all become active.

✅
To disconnect, click the Disconnect button in the top-right corner. The connection is closed and the login modal reappears.

✏️ SQL Editor

Writing and executing SQL statements.

The left pane is the SQL editor. It opens pre-loaded with the HANA_Configuration_Overview_2.00.040+ mini-check as a starting reference. Clear it or overwrite it at any time.


ActionHow
ExecuteClick ▶ Run or press F5 or Ctrl+Enter
Tab indentPress Tab — inserts 2 spaces (browser default Tab behaviour is overridden)
Clear editorClick Clear
Copy SQLClick the ⊞ (copy) button — copies the full editor content to clipboard

Row limit

Three radio buttons control how many rows are returned per query:

OptionBehaviour
500 (default)Fetches up to 500 rows. Shows a ⚠ warning in the log if the result was capped.
1000Fetches up to 1,000 rows.
AllFetches all rows (fetchall). Use with caution on large result sets.

Comment handling

Lines beginning with -- are stripped before execution. This means SAP HANA mini-check scripts (which are heavily commented) can be pasted and run without modification.

Trailing semicolon

A trailing semicolon is removed automatically before sending the SQL to HANA. You do not need to add or remove it.

⚠️
The editor supports only single statements. Do not paste a script with multiple ;-separated statements — only the first will run (and stripping the trailing semicolon may cause a parse error with multi-statement input).

▶▶ Basic Bundle

Running all 35 standard diagnostic scripts in one click.

Click ▶▶ Basic Bundle in the header (visible after connecting). A progress modal appears and the server runs all 35 bundled scripts sequentially in a background thread.


IndicatorMeaning
Progress barFills from 0 to 100 % as each script completes
Counter (N / 35)Shows how many scripts have been processed
Current script nameShows which script is executing right now
Skipped listScripts that were skipped are listed with the reason (file not found, SQL error, etc.)
Download linkWhen complete, a link appears to download the consolidated output file

Output file

The bundle produces a single .txt file saved to the output\ folder:

Consolidated_minichecks_basic_bundle_YYYYMMDD.txt

The file contains a header section (scripts executed / skipped counts) followed by each script's CSV output, separated by ════ dividers with the filename as a label. Each script returns up to 500 rows.

ℹ️
Only one Basic Bundle can run at a time. If a bundle is already running, clicking the button again returns an error. Wait for the progress bar to reach 100 % before starting another.
⚠️
Scripts whose .txt file is not present in mini_checks\ are skipped silently (counted as "skipped — file not found"). This is normal if you have a partial mini-checks library.

🗂️ Consolidate Output Files

Merging individual output files into a single review document.

Click 📄 Consolidate in the header (visible after connecting) to open the Consolidate modal.


  1. Select filesAll .csv and .txt files in the output\ folder are listed with their sizes. Check the boxes for the files you want to merge. Use Select all to check everything.
  2. Click ▶ ConsolidateThe server reads each selected file and appends it to a new file with a ════ separator and filename label between each section.
  3. Download the resultA download link appears immediately. The merged file is also saved in output\ as Consolidated_minichecks_review_YYYYMMDD.txt.

🔧 Troubleshooting

Common problems and how to resolve them.

The browser does not open automatically

ℹ️
Navigate manually to http://127.0.0.1:5000. The server is running but Windows may have blocked the automatic browser launch. Check that webbrowser can find a default browser in the registry.

Port 5000 is already in use

⚠️
Find and stop the process using port 5000: 
netstat -ano | findstr :5000
Or edit the last lines of minichecks_console_V2.0.py and change the port: 
host, port = "127.0.0.1", 5001   # ← change to any free port
Then update run_minichecks.bat to reflect the new URL.

ImportError: No module named 'hdbcli'

⚠️
The lib\ folder is missing or not alongside the script. Verify:
  • lib\pyhdbcli.pyd exists
  • lib\hdbcli\ folder exists
  • Python is 64-bit 3.10+ (run python -c "import struct; print(struct.calcsize('P')*8)" — must return 64)
  • You are running the script from its own directory, not from a different folder

Connection fails: "connection refused" or "timeout"

⚠️
  • Confirm the HANA host is reachable: ping <hostname>
  • Confirm the port is open: telnet <hostname> 30241 (or use Test-NetConnection in PowerShell)
  • Verify the port matches the tenant DB — formula: 3<InstanceNumber>41 for tenants, 3<InstanceNumber>13 for SystemDB
  • Check that your HANA user account is not locked in SYS.USERS

Chart tab is blank / chart never renders

⚠️
lib\chart.umd.min.js is missing. Download it: 
https://cdn.jsdelivr.net/npm/chart.js/dist/chart.umd.min.js
Save as chart.umd.min.js in the lib\ folder, then restart the app. No browser cache refresh needed — the file is served locally.

Basic Bundle completes but many scripts are skipped

ℹ️
Each skipped script lists its reason in the modal (file not found, SQL error, etc.).
  • File not found — add the missing .txt scripts to mini_checks\
  • SQL error — the script may require a higher HANA revision than your system. Check the filename suffix (e.g. 2.00.070+) against your HANA version in M_SYSTEM_OVERVIEW.

Slow execution / long-running queries

💡
There is no query timeout configured. If a query hangs, press Ctrl+C in the console window to stop the server (this also cancels the HANA connection) and restart. Long-running mini-check scripts on busy systems are normal — the statistics server aggregation tables can be large.
